## Why

`code_parallel`'s two real-world callers — `issue_to_pr.json` and `address_pr.json` — go straight from `merge_worktrees` to `git_push`/`pr_create` with no check that the parallel coding agents actually did what `tasks.md` asked, and no cleanup of the OpenSpec change artifacts before the PR is opened. The only workflow that runs `openspec validate`/`archive` at all (`openspec_development.json`, via `openspec_finalize`) is a separate, rarely-used entry point that doesn't retry on failure — it just dead-ends with no PR. The result: every `code_parallel`-driven PR ships unverified, leaves the OpenSpec change lingering in the repo, and gives reviewers (human or AI) only a pointer to files on disk instead of the actual proposal, and a one-line PR body instead of a real summary.

## What Changes

- Add a bounded, fail-closed verification loop to `code_parallel.json` after `merge_worktrees`: run each subtask's declared `Test:` command for real against the merged worktree, plus a read-only semantic judge pass comparing the diff to `proposal.md`/`design.md`/`specs/**`/`tasks.md`. On failure, run one consolidated fixup `coding_agent` against the merged worktree (not a re-fork) and re-check; on exhausting the iteration cap, terminate with no archive and no PR.
- Give both the original per-subtask `coding_agent` and the new fixup `coding_agent` explicit access to run each subtask's declared `Test:` command, since `coding_agent`'s `allowedTools` input replaces the default tool allowlist rather than merging with it — omitting this would silently deny any test command that isn't already one of the handful of hardcoded default runners.
- Remove the two speculative, differently-shaped worker tasks (`openspec_change_validation`, `openspec_archive` / `validate_changes`, `archive`) added ahead of this change — they duplicate `openspec_finalize`'s already-working sequence with an unverified argument shape and were never wired into any workflow. **BREAKING**: those two new worker tasks and their CLI wrappers are removed. `code_parallel.json` does **not** archive the OpenSpec change itself: archiving stays a fully manual, out-of-band step a human runs (via `openspec_finalize`'s existing, unchanged path in `openspec_development.json`, or the `openspec` CLI directly) after the PR merges. This is a deliberate reversal of an earlier version of this change — see design.md Decision 6 — after repeated `openspec archive`-time failures in live runs; no automated post-merge archive trigger is built here.
- Wire the verification loop into `code_parallel.json` itself so `issue_to_pr.json` and `address_pr.json` inherit it automatically, with no changes needed at the call sites beyond consuming the new outputs.
- Embed `proposal.md`'s content verbatim in `openspec_plan.json`'s `plan_review` human-approval draft, and render it in the TUI's approval modal, so a human reviewer sees the actual proposal instead of a path to go read themselves.
- Replace the hardcoded one-line PR bodies in `issue_to_pr.json` and `address_pr.json` (and `openspec_finalize`'s default body) with a deterministic `JSON_JQ_TRANSFORM` step that composes `proposal.md` text, the subtask list, the verification loop's findings, and cost/token totals into a structured markdown PR body.

## Capabilities

### New Capabilities
- `harness-implementation-verification`: Defines the bounded, fail-closed correctness gate that runs after `code_parallel`'s fan-out/merge — real test execution plus a semantic judge, a single consolidated fixup pass on failure, and the tool-allowlist behavior required for declared `Test:` commands to actually run.
- `harness-change-archival`: Defines that `code_parallel` (and its callers `issue_to_pr`/`address_pr`) does **not** archive the OpenSpec change automatically — archiving remains an out-of-band, human-run step after the PR merges — and that the two superseded, never-wired-in bespoke validate/archive worker tasks are removed.
- `harness-pr-summary`: Defines the deterministic, data-driven composition of PR bodies (proposal text, subtask list, verification findings, cost/token totals) consumed by `issue_to_pr` and `address_pr`.

### Modified Capabilities
- `harness-openspec-planning`: The human review branch of `plan_review`'s `DO_WHILE` loop now embeds `proposal.md`'s verbatim content in the review draft, instead of only a path/summary pointing at it.

## Impact

- **Workflows:** `coding-harness/workers/workflows/code_parallel.json` (new verification loop after `merge_worktrees`; no archive step — archiving remains manual/out-of-band), `code_subtask.json` (explicit `allowedTools` for the declared `Test:` command), `issue_to_pr.json` and `address_pr.json` (consume the enriched PR-body inputs; no longer construct terse bodies inline), `openspec_plan.json` (`plan_review` draft carries `proposal.md` content).
- **Workers:** `coding-harness/workers/openspecops/tasks.py` and `coding-harness/workers/common/openspec_cli.py` (remove `openspec_change_validation`/`openspec_archive` and `validate_changes`/`archive`, unused speculative duplicates of `openspec_finalize`), `coding-harness/workers/common/tool_policy.py`-adjacent wiring (allowlist composition for subtask/fixup test commands). `coding-harness/workers/openspec/tasks.py`'s `openspec_finalize` is unchanged and untouched by this change — it continues to serve only `openspec_development.json`.
- **TUI:** `coding-harness/tui/widgets/modals.py` (`ApprovalModal._draft_text` renders the new embedded proposal text for the `openspec_plan` draft kind).
- **Behavior:** `code_parallel`-driven PRs (via `issue_to_pr`, `address_pr`) will now be gated on real verification (real tests + semantic judge + `openspec validate`) before a PR is opened; a run that never passes verification produces no PR instead of an unverified one. The OpenSpec change directory remains in the repo — and therefore in the PR's diff, for reviewer visibility — after a successful run; archiving it is a separate, manual step a human performs after the PR merges.
